# 根拠付き人物情報の取得・監査

公明党所属議員の担当B群1,320人を処理した取得・監査コードです。入力の `id`、`municipalityCode`、`name` を維持し、確認できた新規情報と人物別の取得結果を出力します。既存の人物情報・既存findingは、統合側で保持してください。

2026-11-05の確定結果は、情報追加848人・新規7,295件、既存内容確認59人、追加根拠未確認412人、取得失敗1人です。新規出典はすべて本人発信です。本人の公開記載を確認したもので、職歴・役職・政策成果の第三者による裏付け調査ではありません。

## 実行

Python 3.10以上を使用します。

```bash
python3 -m pip install -r requirements.txt
export KOMEI_B_INPUT=/path/to/komei-b.json
export KOMEI_B_OUTPUT=/path/to/output/enriched-komei-b.json
export KOMEI_B_CACHE=/path/to/private-cache/komei-b
export KOMEI_B_LEGACY_CACHE=/path/to/private-cache/legacy
python3 enrich-komei-b.py --limit 100
```

未処理分がなくなるまで、同じ設定で100人ずつ通常の新プロセスを起動します。長時間の接続不調を避けるための区切りです。同じ入力・出力を複数プロセスから同時に処理しないでください。出力は入力順、25人ごとに保存されます。全件が揃うまでは `PARTIAL`、全件終了時は `COMPLETE` と表示します。

取得済み資料を統一規則で再解析する場合は、次を実行します。ネットワークへ追加アクセスせず、保存済みHTMLを使います。

```bash
python3 enrich-komei-b.py --offline --reparse
python3 validate-komei-b.py
```

公開・統合は監査が通った全件出力を対象にしてください。取得失敗時に既存情報を削除する処理はありません。

## 環境変数

| 変数 | 用途・既定値 |
|---|---|
| `KOMEI_B_WORKDIR` | 作業基準ディレクトリ。既定は実行時のカレントディレクトリ |
| `KOMEI_B_INPUT` | 入力JSON。既定は作業基準ディレクトリの `komei-b.json` |
| `KOMEI_B_OUTPUT` | 出力JSON。既定は作業基準ディレクトリの `enriched-komei-b.json` |
| `KOMEI_B_CACHE` | 取得HTMLの保存先。既定は作業基準ディレクトリの `.cache/komei-b` |
| `KOMEI_B_LEGACY_CACHE` | 旧取得HTMLの参照先。既定は `.cache/komei-b-legacy` |
| `KOMEI_B_JOURNAL` | 再開用ログ。既定は出力JSONと同じ場所・同じ名前の `.jsonl` |
| `KOMEI_B_STATS` | 監査集計の保存先。既定は出力JSONと同じ場所の `*-stats.json` |
| `KOMEI_B_CHECKED_AT` | 確認日。既定は実行日のUTC日付。過去の検証を再現する場合のみ `2026-11-05` 等を明示 |
| `KOMEI_B_FORCE_FETCH` | `1` で保存済みHTMLを再利用せず取得。`--offline` では無効 |
| `KOMEI_B_PYDEPS` | 任意の追加Python依存ライブラリディレクトリ |

キャッシュの再読込を新しいWeb取得とは扱いません。最新ページを取得する際は新しいcache保存先、または `KOMEI_B_FORCE_FETCH=1` を指定します。同日に全件を再処理する場合は `--reparse` を付け、途中件数での公開を避けてください。

## 出典・本人照合

- 党公式 `/member/detail/` の `.dList06` 内の氏名・フリガナと「公式ホームページ」を使用します。
- 共有ホストでは `/km/本人slug/` の範囲を守り、別人のページや党トップ共通プロフィールへ広げません。
- 別表記は党公式の氏名・フリガナから実証できるものだけです。読みや愛称は推測しません。
- `evidence.matchedName` は実際に照合した表記です。漢字名と異なる場合は `identitySourceURL` を元入力の党プロフィールURLと照合してください。統合時に `matchedName` を正準名へ揃えるなら、実照合表記を `observedMatchedName` 等へ残します。
- 専用プロフィール・政策欄を対象とし、引用、他者の経歴、共通フッター、コメント、サイドバー、行事記事を除外します。
- 新規findingには `matchedName`、`sectionHeading`、`selector`、`rule` の根拠情報を付けます。見出しが画像・空欄の場合は、ページタイトル等を使ったことを明記します。
- 住所、電話、誕生日、家族、医学的私事を出力へ取り込みません。家族見出し・家族のdt/dd配下の経歴も除外します。
- 最大6workers・ホストごと最大2並列。失敗時の再試行は1回までで、その前にHTTPクライアントを作り直します。

## 日付と判断

`checkedAt` は確認日です。掲載基準日を同定できないページの `asOf` は不明とし、取得時点の現職継続を保証しません。過去の保存資料を再確認した場合もあります。

年月が隣接する表セル・dt・段落・改行で示されていれば経歴と結合します。和暦、西暦併記、「同年」などは出典表記を保持し、換算や基準年を推測しません。元職の明示があれば残し、出典の「現職」表記は現在も継続しているとの確認と区別します。

「情報追加」は本人の専用欄に掲載された内容の追加です。政策の実現状況や本人の寄与は未検証です。「既存内容確認」は既存の一部記載と本文を照合した状態で、既存全項目の再検証ではありません。

「追加根拠未確認」「取得失敗」は、画像のみ、氏名不一致、追加できる記載の未確認、接続失敗等を含みます。経歴・活動の不存在という判定ではありません。

## 配布対象

このフォルダは取得・監査コード、依存定義、説明書だけです。原HTML、長い生本文、進捗ログ、cacheは含みません。実行後のcacheには連絡先等を含む原ページが保存され得るため、公開するデータや配布物に同梱しないでください。
